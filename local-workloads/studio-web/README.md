# Imagine together frontend

A local collaboration pilot for people collecting sources, unfinished thoughts, and a shared project brief. This fork preserves the accepted personal studio on the `studio/personal-v1` reference. It runs separately from that app.

Run `npm ci` and `npm run dev`, then open http://127.0.0.1:8790. The Vite development server proxies `/api` to the team backend at 127.0.0.1:8791. Start that backend using the sibling `../team-studio/README.md` instructions. `npm run build` checks TypeScript and builds assets; it does not confer a production tldraw license.

Create a named local account with a password of at least 12 characters. Create a workspace or redeem a privately shared invitation. Owners invite editors/viewers, set required reviewers, and publish approved briefs. Editors contribute source cards, canvas changes, and decisions; they review when designated. Viewers can read and export. Enforcement belongs to the backend; the UI also disables writes and sets tldraw read-only.

The Canvas & sources tab retains the real tldraw canvas and manual swipe file. A canvas card is an editable copy with source ID/revision metadata, not the original source. Changes are saved as versioned snapshots. This is asynchronous shared work: refresh to see another collaborator’s changes. Conflicts pause saving and allow downloading local work before reloading. It is not live multiplayer. Switching workspace flushes pending board saves and reloads the page with an immutable API scope, preventing delayed saves from moving between workspaces.

Alignment & decisions holds a human-authored Markdown brief, supporting source revisions, required reviewers, explicit approvals or requests for changes, and a decision ledger. A reviewer approves an exact saved revision and content fingerprint. Editing the brief, changing the reviewer policy, or changing a cited source requires renewed review. Publication is an explicit owner action after required approvals. Unsaved text remains in the editor after a conflict. A ledger entry records a choice and rationale; it does not substitute for approval. AI never agrees on a person’s behalf.

Optional Bonsai suggestions stay separate until explicitly appended to a team note. Applying text uses the source revision captured by the job and records the suggestion ID; it never rewrites the quotation. Useful/Not useful is a distinct, explicit feedback action. Job evidence is downloaded through the authenticated workspace API; collaborators are not sent to an unscoped local MLflow dashboard. Recent jobs survive reload. Manual work remains usable without inference.

Export/restore covers workspace artifacts with backend validation and ownership rules; restoring can invalidate prior approvals and should not be used to merge collaborator edits. Exported files may contain private project material: share them intentionally. The verified learning CTA is [Learn with Jai on Maven](https://maven.com/a-plus); no workshop date or paid workshop destination is asserted.

The tldraw 5.4.2 SDK runs here in local development mode with its attribution intact and locally packaged assets. Public deployment/distribution needs the appropriate [tldraw license](https://tldraw.dev/community/license). A later live collaboration deployment additionally needs authenticated workspace-scoped sync rooms and durable room storage per the [official sync guide](https://tldraw.dev/docs/sync). The present pilot does not use a public demo sync service.

`node verify-collaboration.mjs` is the explicit real-backend browser integration check. It creates clearly labeled fixture accounts and workspaces in the fork service, exercises manual authoring/roles/approval/exports, and makes **no model requests**. Its fixtures need cleanup by the operator after retaining the local receipt. It must never target the original personal service. `node verify-browser.mjs` exercises workspace-scoped frontend APIs with in-memory fixtures, including AI evidence download, explicit feedback/application provenance, canvas drag/persistence/conflicts, and backup validation. It makes no real API calls. The historical `verify-real.mjs` is disabled in this fork to prevent accidental access to the original personal service. Screenshots and receipts belong under ignored `verification/`.

The [product brief and ADRs](../../../docs/studio/collaboration/README.md) distinguish this local pilot from production work: TLS/identity lifecycle, tested PostgreSQL migrations and restore, durable worker operations, workspace access to all evidence, accessibility review, and a licensed collaboration deployment.
